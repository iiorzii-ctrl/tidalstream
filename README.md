# tidalstream

海上保安庁「潮流推算」ページ
（`https://www1.kaiho.mlit.go.jp/TIDE/pred2/cgi-bin/CurrPredCgi_K.cgi?area=01`）
の図を、**指定時刻から1時間ごとに3枚、横に並べて**表示するビューアです。
さらに、**図の上の観測地点をクリックすると、その地点の流速の推移**をグラフと表で表示します。

外部パッケージへの依存はありません（Node.js 18 以上の標準機能のみ）。

## 使い方

```bash
node server.mjs          # または npm start
# → http://127.0.0.1:3000
```

画面で「海域・日付・開始時刻・間隔・枚数」を指定して「表示」を押すと、
`09:00 / 10:00 / 11:00` のように1時間ずつずれた図が横一列に並びます。
枚数と間隔は変更でき（既定は 1時間おきに3枚）、「毎時自動更新」を有効にすると
毎正時に現在時刻へ追従して読み直します。時刻はすべて日本標準時です。
海域は東京湾ほか 01〜20 から選べます。

環境変数: `PORT`（既定 3000）、`HOST`（既定 127.0.0.1）。

### 特定地点の流速

潮流図の上にマウスを乗せると観測地点の位置が薄く表示されます（既定では図を隠さない
ように出していません）。地点をクリックすると、その地点の流速の推移を
グラフ・表・CSV で確認できます。期間は 12/24/48 時間から選べます。

選んだ地点はブラウザに記憶され、次回開いたときも復元されます。

**取得できるのは流速（ノット）のみで、流向は含まれません。** 上流ページが画像に
重ねている `USEMAP` に流速しか入っていないためです。流向は図の矢印を見てください。

### HTTP プロキシ配下で動かす場合

Node.js の `fetch` は `HTTPS_PROXY` を自動では読みません。プロキシ必須の
環境では、迂回して弾かれる（403 になる）ため次のように起動します。

```bash
NODE_USE_ENV_PROXY=1 node server.mjs   # Node 22.21 以降
```

## 仕組み

上流ページの URL の組み立て方を決め打ちせず、**実行時にページを解析**します。

1. 基準ページを1回取得し、`<form>` 内の `select` / `input` を読む
2. 各項目が「年・月・日・時・分・海域」のどれかを、`name` のヒントと
   選択肢の並び（0〜23 の24個なら「時」、1〜12 の12個なら「月」…）から推定する
3. 推定した「時」のパラメータだけを 1時間ずつずらして、必要な枚数ぶんページを取得する
4. 各ページの `<img>` を点数付けし（サイズ・動的 URL・ロゴやボタンらしい名前かどうか）、
   潮流図らしいものを選ぶ
5. 画像は `/api/image` 経由で中継する（`Referer` を付けて取得し、結果をキャッシュする）

この作りなので、`hh` / `hour` / `time` のようなパラメータ名の違いや、
`01` と `1` のような 0 埋めの違いは自動で吸収されます。

## 実サイトで確認した仕様（2026-08 時点）

実ページを解析して確認した内容です。上流の作りが変わったときの手掛かりとして残します。

| 項目 | 実際の値 |
| --- | --- |
| パラメータ | `area` / `year` / `month` / `day` / `hour`（0 埋めなし、`min` は無い） |
| 例 | `CurrPredCgi_K.cgi?area=01&year=2026&month=8&day=1&hour=10` |
| 文字コード | UTF-8 |
| 潮流図 | `../CurrPred/curr_img/<海域>_<YYYYMMDDHH>_.png`（1ページに1枚） |
| 流速 | `<AREA coords=x,y,r ALT="1.5kn.">`（東京湾で41地点。座標は時刻をまたいで一定） |
| 海域 | 01〜20（01=東京湾, 02=伊勢湾, …, 20=宮古島・石垣島・西表島） |
| 有効期間 | 西暦1年〜2200年 |

注意すべき点として、**フォームは `document.write` で JavaScript の文字列として
出力されており**、`value=\"01\"` のようにクォートがエスケープされています。
解析前にエスケープを戻しています（`src/scraper.mjs` の `discoverForm`）。

上流の作りが変わったときは、次を実行すると現在のフォーム構成・判定結果・
画像候補が一覧で出ます。

```bash
node scripts/inspect.mjs 01
```

自動判定が外れていた場合は `src/config.mjs` の以下を直せば追従できます。

- `FORM_ROLE_HINTS` … パラメータ名から役割を判定する正規表現
- `FALLBACK_PARAM_NAMES` … フォームが見つからないときに使う名前
- `PAGE_URL` / `ALLOWED_HOSTS` … 取得先

画面上でも、各パネルの「候補」プルダウンから別の画像を選び直せます
（選んだ順位は次回以降も使われます）。

## API

| エンドポイント | 内容 |
| --- | --- |
| `GET /api/frames?area=01&date=2026-08-01&hour=9&step=1&count=3` | 各時刻の画像 URL と全地点の流速を JSON で返す |
| `GET /api/series?area=01&date=2026-08-01&hour=9&hours=24&x=190&y=395` | 指定地点の流速の推移 |
| `GET /api/series.csv?...` | 同じ内容を CSV で（Excel 用に BOM 付き） |
| `GET /api/areas` | 海域コードの一覧 |
| `GET /api/image?u=<画像URL>&r=<参照元ページ>` | 画像の中継（許可ホストのみ） |
| `GET /api/debug?area=01` | 上流ページの解析結果をそのまま返す |

## 取得先への配慮

相手は公共機関のサーバなので、次の制限を入れています
（`src/config.mjs` で調整可能）。

- 上流への同時接続は 2 本まで
- ページは 10 分、画像は 30 分キャッシュし、同じ URL を繰り返し叩かない
- 20 秒でタイムアウト
- 連絡先を含む User-Agent を送る

画像の著作権は海上保安庁にあります。利用の際は
[海上保安庁のサイト利用規約](https://www.kaiho.mlit.go.jp/) を確認してください。

## テスト

```bash
node --test 'tests/**/*.test.mjs'
```

ネットワークには接続せず、次の2通りで確認します。

- `tests/fixtures/real-page.html` … 実サイトの応答をそのまま保存したもの。
  パラメータ名の判定・エスケープされた属性値の解釈・画像の抽出・
  組み立てた URL がページ自身の「1時間後」ボタンと一致することを確認
- `tests/stub-upstream.mjs` … 時刻ごとに別の画像を返すスタブ。3枚の取得・
  日付をまたぐ時刻計算・HTTP エンドポイント・SSRF 防止・キャッシュを確認
  （実サイトが UTF-8 でも Shift_JIS のページを読めることの確認を兼ねる）
