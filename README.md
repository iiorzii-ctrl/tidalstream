# tidalstream

海上保安庁「潮流推算」ページ
（`https://www1.kaiho.mlit.go.jp/TIDE/pred2/cgi-bin/CurrPredCgi_K.cgi?area=01`）
の図を、**指定時刻から1時間ごとに3枚、横に並べて**表示するビューアです。
さらに、**図の上の観測地点をクリックすると、その地点の流速の推移**をグラフと表で表示します。

外部パッケージへの依存はありません（Node.js 18 以上の標準機能のみ）。

## 使い方

```bash
node server.mjs          # または npm start
# → http://127.0.0.1:3000
```

画面で「日付・開始時刻・間隔・枚数」を指定して「表示」を押すと、
`09:00 / 10:00 / 11:00` のように1時間ずつずれた図が横一列に並びます。
枚数と間隔は変更でき（既定は 1時間おきに3枚）、「毎時自動更新」を有効にすると
毎正時に現在時刻へ追従して読み直します。時刻はすべて日本標準時です。
海域は**東京湾のみ**です。選択欄は表示されません（`ALLOWED_AREAS` で増やせます）。

**開いたときは常に現在時刻から始まります。** 海域・間隔・枚数は前回の指定を
引き継ぎますが、日時は引き継ぎません（ブックマークや共有リンクに残った
古い日時で開いてしまわないようにするため）。

環境変数:

| 変数 | 既定 | 内容 |
| --- | --- | --- |
| `PORT` | 3000 | 待ち受けポート |
| `HOST` | 127.0.0.1 | 待ち受けアドレス。他の端末から見るなら `0.0.0.0` |
| `AUTH_USER` / `AUTH_PASS` | なし | 両方設定すると Basic 認証が有効になる |
| `ACCESS_TOKEN` | なし | 設定すると「秘密のリンク」で入れるようになる（下記） |
| `ALLOWED_AREAS` | `01` | 使う海域コード。カンマ区切りで増やせる（例: `01,02`） |
| `MAX_DATE_OFFSET_DAYS` | 7 | 指定できる日付を今日の前後何日までにするか |
| `RATE_LIMIT_PER_MIN` | 90 | 同一の相手から1分あたり受け付ける数 |

### 特定地点の流速

潮流図の上にマウスを乗せると観測地点の位置が薄く表示されます（既定では図を隠さない
ように出していません）。地点をクリックすると、その地点の流速の推移を
グラフ・表・CSV で確認できます。期間は 12 時間に固定しています（理由は下記）。

選んだ地点はブラウザに記憶され、次回開いたときも復元されます。

**取得できるのは流速（ノット）のみで、流向は含まれません。** 上流ページが画像に
重ねている `USEMAP` に流速しか入っていないためです。流向は図の矢印を見てください。

### 別の端末から見る（iPad・職場の PC など）

#### 同じ Wi-Fi 内だけでよい場合

```bash
HOST=0.0.0.0 node server.mjs
# → 同じネットワークの端末から http://<この PC の IP>:3000
```

#### どこからでも見たい場合

サーバに置いて Basic 認証を掛けます。**認証なしで外部に公開しないでください。**
誰でもアクセスでき、その分だけ上流（海上保安庁）のサーバにリクエストが飛びます。

```bash
AUTH_USER=好きな名前 AUTH_PASS=十分に長いパスワード HOST=0.0.0.0 node server.mjs
```

`AUTH_USER` と `AUTH_PASS` の両方を設定したときだけ認証が有効になります。手元で
動かすぶんには設定不要です。制限なしで `0.0.0.0` を待ち受けると起動時に警告が出ます。

##### 少人数に渡すなら「秘密のリンク」のほうが楽

毎回の入力を避けたい場合は、`ACCESS_TOKEN` に長いランダムな文字列を設定します。

```
https://<ホスト>/?k=<ACCESS_TOKEN と同じ文字列>
```

このリンクを一度開くと Cookie（1年）が発行され、以後は素の URL で使えます。
渡す相手にはリンクを1本送るだけで済みます。`AUTH_USER`/`AUTH_PASS` と併用でき、
どちらか一方でも通ります。

リンクが漏れれば誰でも入れる点は Basic 認証より弱いので、下の歯止めと
セットで使ってください。

##### 公開時の歯止め

- **日付の範囲**を今日の前後 7 日に制限（`MAX_DATE_OFFSET_DAYS`）。
  制限が無いと `area × 日付 × 時刻` の組み合わせが天文学的な数になり、
  機械的に辿られると際限なく上流に図を生成させてしまう
- `/robots.txt` で巡回を断る
- 同一の相手からの**流量制限**（`RATE_LIMIT_PER_MIN`、既定 90/分）

`/healthz` と `/robots.txt` だけは制限の対象外です。

#### Render の無料枠に置く手順

`render.yaml` を同梱しているので、設定を書かずに置けます。

1. このリポジトリを GitHub に push する
2. [dashboard.render.com](https://dashboard.render.com) で **New → Blueprint**
3. このリポジトリを選ぶ。`render.yaml` が読まれ、内容が表示される
4. `AUTH_USER` と `AUTH_PASS` の入力欄が出るので値を入れる
   （パスワードは推測されにくい長いものにしてください）
5. Apply を押す。数分で `https://tidalstream-xxxx.onrender.com` のような URL が出る
6. iPad や職場の PC でその URL を開き、手順4の値でログインする

`render.yaml` の中身:

| 設定 | 値 | 理由 |
| --- | --- | --- |
| `plan` | `free` | 無料枠 |
| `region` | `singapore` | 上流が日本にあるため近いところを選ぶ |
| `buildCommand` | 何もしない | 依存パッケージが無いのでビルド不要 |
| `healthCheckPath` | `/healthz` | 認証の対象外なので死活監視が通る |

**無料枠は一定時間アクセスが無いと停止します。** 次にアクセスしたときに起動し直すため、
その1回だけ 30〜60 秒ほど待たされます。2回目以降は普通に動きます。待ち時間を無くしたい
場合は有料プランにするか、下の Cloudflare Tunnel を使ってください。

実測のメモリ使用量は最大 90MB 程度（起動直後 60MB）なので、無料枠の制限には余裕があります。

#### 手元の PC を外から見る（デプロイしない方法）

PC を起動しておく必要がありますが、待ち時間ゼロで無料です。

```bash
node server.mjs
cloudflared tunnel --url http://localhost:3000
```

#### その他のホスティング

`Dockerfile` も同梱しているので、Fly.io・Railway・Cloud Run など Docker が使える
ところにもそのまま載ります。

iPad では Safari の共有メニューから「ホーム画面に追加」すると、アプリのように開けます。

### HTTP プロキシ配下で動かす場合

Node.js の `fetch` は `HTTPS_PROXY` を自動では読みません。プロキシ必須の
環境では、迂回して弾かれる（403 になる）ため次のように起動します。

```bash
NODE_USE_ENV_PROXY=1 node server.mjs   # Node 22.21 以降
```

## 仕組み

上流ページの URL の組み立て方を決め打ちせず、**実行時にページを解析**します。

1. 基準ページを1回取得し、`<form>` 内の `select` / `input` を読む
2. 各項目が「年・月・日・時・分・海域」のどれかを、`name` のヒントと
   選択肢の並び（0〜23 の24個なら「時」、1〜12 の12個なら「月」…）から推定する
3. 推定した「時」のパラメータだけを 1時間ずつずらして、必要な枚数ぶんページを取得する
4. 各ページの `<img>` を点数付けし（サイズ・動的 URL・ロゴやボタンらしい名前かどうか）、
   潮流図らしいものを選ぶ
5. 画像は `/api/image` 経由で中継する（`Referer` を付けて取得し、結果をキャッシュする）

この作りなので、`hh` / `hour` / `time` のようなパラメータ名の違いや、
`01` と `1` のような 0 埋めの違いは自動で吸収されます。

## 実サイトで確認した仕様（2026-08 時点）

実ページを解析して確認した内容です。上流の作りが変わったときの手掛かりとして残します。

| 項目 | 実際の値 |
| --- | --- |
| パラメータ | `area` / `year` / `month` / `day` / `hour`（0 埋めなし、`min` は無い） |
| 例 | `CurrPredCgi_K.cgi?area=01&year=2026&month=8&day=1&hour=10` |
| 文字コード | UTF-8 |
| 潮流図 | `../CurrPred/curr_img/<海域>_<YYYYMMDDHH>_.png`（1ページに1枚） |
| 流速 | `<AREA coords=x,y,r ALT="1.5kn.">`（東京湾で41地点。座標は時刻をまたいで一定） |
| 海域 | 01〜20（01=東京湾, 02=伊勢湾, …, 20=宮古島・石垣島・西表島） |
| 有効期間 | 西暦1年〜2200年 |

注意すべき点として、**フォームは `document.write` で JavaScript の文字列として
出力されており**、`value=\"01\"` のようにクォートがエスケープされています。
解析前にエスケープを戻しています（`src/scraper.mjs` の `discoverForm`）。

上流の作りが変わったときは、次を実行すると現在のフォーム構成・判定結果・
画像候補が一覧で出ます。

```bash
node scripts/inspect.mjs 01
```

自動判定が外れていた場合は `src/config.mjs` の以下を直せば追従できます。

- `FORM_ROLE_HINTS` … パラメータ名から役割を判定する正規表現
- `FALLBACK_PARAM_NAMES` … フォームが見つからないときに使う名前
- `PAGE_URL` / `ALLOWED_HOSTS` … 取得先

画面上でも、各パネルの「候補」プルダウンから別の画像を選び直せます
（選んだ順位は次回以降も使われます）。

## API

| エンドポイント | 内容 |
| --- | --- |
| `GET /api/frames?area=01&date=2026-08-01&hour=9&step=1&count=3` | 各時刻の画像 URL と全地点の流速を JSON で返す |
| `GET /api/series?area=01&date=2026-08-01&hour=9&x=190&y=395` | 指定地点の流速の推移（12 時間ぶん） |
| `GET /api/series.csv?...` | 同じ内容を CSV で（Excel 用に BOM 付き） |
| `GET /api/areas` | 使える海域コードの一覧（既定では東京湾のみ） |
| `GET /api/image?u=<画像URL>&r=<参照元ページ>` | 画像の中継（許可ホストのみ） |
| `GET /api/debug?area=01` | 上流ページの解析結果をそのまま返す |

## 取得先への配慮

相手は公共機関のサーバで、しかもリクエストのたびに潮流を計算して PNG を
生成しています。次の制限を入れています（`src/config.mjs` で調整可能）。

- 上流への同時接続は 2 本まで
- 20 秒でタイムアウト
- 連絡先を含む User-Agent を送る
- メモリキャッシュ（ページ 10 分・画像 30 分）
- **ディスクへの永続キャッシュ**（下記）
- 推移の期間は 12 時間に固定（下記）
- 海域は東京湾だけに限定（`ALLOWED_AREAS`）。開けていない海域を頼まれたら、
  上流に触らずに 400 で断る
- 画像の中継（`/api/image`）は、クエリの無い画像ファイルの URL だけ通す。
  上流の CGI は「ページを返す」と「図を描く」が同じ入口なので、ここを
  素通しにすると海域と日付の制限を迂回して図を描かせられてしまうため

### 期間を絞っている理由

上流の CGI は「ページを返す」と「図を描く」が分かれていません。**流速の数値は
HTML に書かれているので画像を受け取る必要はありませんが、リクエストした時点で
相手側では図が生成されます。**

実測（推移を1回表示したとき）:

| 期間 | 相手側で生成される図 | こちらが受け取る画像 |
| --- | --- | --- |
| 24 時間 | 25 枚 | 3 枚 |
| 12 時間 | 13 枚 | 3 枚 |

受け取らない図のぶんも相手の計算量になるため、期間は 12 時間に固定しています
（選択肢そのものを設けていません）。潮流は半日周期なので、12 時間あれば
山と谷が1回ずつ入ります。長い期間が要る場合は `SERIES_HOURS`（`public/app.js`）と
`server.mjs` の上限を上げてください。

なお永続キャッシュにより、同じ日時の図が生成されるのは最初の1回だけです。

### 永続キャッシュ

潮流推算は天文計算なので、**同じ (海域, 日時) の結果は永久に変わりません**
（時間を空けて取得しても41地点すべての値が一致することを確認済み）。
そのため日時を指定したページと、ファイル名に日時を含む画像は期限を設けずに
`.cache/` に保存し、**同じ日時は生涯で1回しか取りに行きません**。

日時を指定しない基準ページは「現在時刻」が初期値として入るため対象外です。

実測（実サイト、同じ日時を2回）:

| | 3枚の表示 | 24時間の推移 |
| --- | --- | --- |
| 初回 | 3.4秒 | 5.1秒 |
| 再起動後（ディスクから） | 1.7秒 | **0.0秒**（上流へのリクエスト 0 回） |

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `TIDALSTREAM_CACHE_DIR` | `.cache/` | 保存先 |
| `TIDALSTREAM_CACHE_MAX_MB` | 200 | 上限。超えると古いものから削除 |
| `TIDALSTREAM_NO_DISK_CACHE` | — | `1` で無効化 |

キャッシュを消したいときは `.cache/` を削除してください。なお Render の
無料枠はファイルシステムが揮発するため、停止のたびにキャッシュは失われます。

## 利用規約について

上流サイトは
[政府標準利用規約（第2.0版）に準拠した利用ルール](https://www1.kaiho.mlit.go.jp/copyright.html)
を定めており、出典を記載すれば商用を含めて自由に利用できます。リンクも自由で、
許可・連絡は不要です。`/TIDE/pred2/` は `robots.txt` の `Disallow` 対象外です。

これに従い、画面のフッターに次を表示しています。

- 出典（「潮流推算」海上保安庁 海洋情報部ホームページ＋リンク）
- 潮流図はそのまま表示し、グラフ・表・CSV は値をもとに当ツールが作成したものである旨
- 航海には使用せず、海図など正規の資料を参照してほしい旨

なお同ルールには、水路業務法第25条により**海図・航空図・水路誌・灯台表に
類似の刊行物を発行する場合は許可が必要**である旨の注意があります。潮流推算図は
この4種には当たらないと考えられますが、広く一般に公開・配布する形にする場合は
事前に確認してください。
